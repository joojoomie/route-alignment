\section{Characterising the recordings}

\textbf{Provenance.} Picture counts, rasters and picture order are parsed from
the HEVC Annex-B bitstream by a purpose-written scanner, independently of
libavcodec; the two agree exactly on all four files. Nominal 10\,FPS is
stream-declared; timestamp statistics come from the integer-nanosecond sidecars
and describe capture-log events, not decoded-video cadence.

\subsection{Four findings that silently corrupt data}

\begin{itemize}
  \item \textbf{Decode order is not display order for 74.4\% of pictures.} A
  four-frame B-pyramid: bitstream order runs 0, 4, 2, 1, 3, 8, 6, 5, 7. Any tool
  calling the $n$-th packet ``frame $n$'' scrambles the sequence locally, by the
  same magnitude as the error being measured. The pipeline reconstructs picture
  order and \emph{fails} unless display order is a clean permutation.
  \item \textbf{The declared frame rate contradicts itself.} FFprobe reports
  \texttt{r\_frame\_rate 10/1} from the stream and \texttt{avg\_frame\_rate 25/1}
  as its own fallback. Both are declared; neither is measured.
  \item \textbf{Colour is undeclared.} Only \texttt{color\_range=tv} is signalled;
  swscale picks a matrix from frame height (BT.709 for the source, BT.601 for a
  480-tall proxy). Pinning it changes 3.17\% of decoded bytes; cache keys carry
  source hash, raster and colour.
  \item \textbf{Coded raster is $1440\times1088$}, cropped to $1440\times1080$ by
  an 8-row conformance window; all four file sizes are exact multiples of 4096.
\end{itemize}

\subsection{What the cameras actually are}

CAM0 faces left and CAM5 right; both are wide fisheye with heavy vignetting and
neither faces forward: the scene sweeps laterally across CAM5 at a median
\SweepRateCamFive{}\,px per frame at the \SweepRaster{} geometry raster
($\approx$\,\SweepRateCamFiveNative{}\,px at native \SweepNativeWidth{}; CAM0
\SweepRateCamZero{}/\SweepRateCamZeroNative{}). That sets the difficulty:
appearance depends on lateral lane position far more than on a forward camera,
and a place is re-observed only when traversed in the same direction. A near/far
scale test for lane offset flags \LateralFlaggedCamZero{}/\LateralFlaggedCamFive{}
of sampled pairs without persistence in time ($p{=}\LateralSignP$ on the
opposite-sign test): no lane offset is established where the test can see.

Run B is 2.2$\times$ darker (mean luma 30.1/38.3 against 65.3/82.6), half as
sharp, and has \textbf{rain on the lens that is static for the whole recording}:
the droplets are crisp in both the temporal median and the temporal
standard-deviation map, which only a fixed feature can be. That makes them
measurable without a learned model, as

\subsection{Route topology}

Retrieval over the matcher's own descriptors finds a strong tail-to-head revisit
in all four sequences (Run A \TopologyCamZeroPair{} at cosine
\TopologyCamZeroCosine{} on CAM0, \TopologyCamFivePair{} at
\TopologyCamFiveCosine{} on CAM5; Run B \TopologyCamZeroRunBPair{}/%
\TopologyCamZeroRunBCosine{} and \TopologyCamFiveRunBPair{}/%

of the \TopologyEligiblePairs{} Run A frame pairs more than \TopologySeparation{}
frames apart, \TopologyAliasFractionCamFive{} exceed cosine \TopologyCosine{} on
CAM5 against \TopologyAliasFractionCamZero{} on CAM0, \TopologyRatio$\times$ the
density of look-alike places (\TopologyRatioRange$\times$ across cosine
0.80--0.90). And the A\,$\to$\,B offset is not constant: dynamic time warping on
an illumination-robust descriptor puts it between $-112$ and $+12$ frames, a
\textbf{12.4-second drift} the annotator's independent labels reproduce ($-89$
to $+13$). A fixed offset is wrong by over ten seconds.

\section{Method}

\subsection{Each stage answers an observed failure of the simpler one}

Linear progress drifts 12.4\,s; nearest-neighbour retrieval alone confuses the
repeated awnings and foliage corridors, so route order and local verification
are added; forced dense output cannot be right where nothing corresponds, so the
method abstains.

\vspace{1pt}
\begin{center}
\fcolorbox{rulegray}{pale}{%
\begin{minipage}{0.955\textwidth}
\centering\small
\textbf{Canonical decoded image}
$\rightarrow$ reliability mask
$\rightarrow$ frozen DINOv2-S descriptor
$\rightarrow$ full-route coarse similarity
$\rightarrow$ monotonic path with a slope prior
$\rightarrow$ full-cadence refinement
$\rightarrow$ local RootSIFT/RANSAC
$\rightarrow$ \textbf{accept or abstain}
\end{minipage}}
\end{center}

The earlier sparse-anchor method (v1) placed 36 fixed Run A anchors per camera
and interpolated only between adjacent accepted ones, so an isolated accept never
propagated. The submitted method (v2) aligns every route frame through a globally
optimised monotonic path, refines to full cadence, tests corridor uniqueness at
four time scales, and verifies geometry with RootSIFT/RANSAC requiring 20
matches, 12 inliers, a 0.25 inlier ratio and support across a $4\times3$ grid.
Both forbid departure--arrival wrap and interpolation across the seam, because
the endpoints alias. The rebuild decodes from the HEVC with pinned colour rather
than from $640\times480$ proxies, uses the measured mask, and runs geometry at a
raster chosen by measurement on labelled-correct development pairs:

\subsection{Evaluation design}

Eighty prediction-blind labels, 40 per camera, on Run A ordinals the 36 anchors
never touched, stratified along the route with parked frames excluded. The page
showed the query frame and a scrubbable Run B filmstrip and nothing else: no
prediction, no score, a deliberately weak linear prior. The method was
\textbf{frozen before the labels were imported} --- every parameter hashed at
15:41:34\,UTC, the seal written at 15:52:15\,UTC citing it --- and a verifier
refuses to score if any live constant has drifted. That records
\emph{ordering}, not custody. v1 was frozen long before these labels existed.

\subsection{A label-semantics correction, made after the fact}

The page offered a match or ``no usable match'', merging two facts: that Run B
has no counterpart here, and that the annotator could not tell. All
\UndeterminedLabels{} such labels meant the second, checkably --- queries were
drawn inside the stretch both runs traversed (Run A 180--2616 into Run B
114--2621), so a genuine absence was impossible by construction. Undetermined
queries therefore leave the denominator. The correction was made \emph{after}
the results were seen, applied identically to both methods, and raises the
denser one more; the table's last column keeps the uncorrected reading.

\subsection{A second blind set, drawn to test what the first one suggested}

With the v2 labels spent, \VthreeLabels{} fresh queries were sealed against a
freeze naming the submitted mapping, the slope variant, the posterior and the
slope gate, and scored once. Half target kinks and dark stretches, half are a
uniform \emph{corridor} control; targeting used the submitted mapping's own
structure, so \textbf{only the corridor stratum is an unbiased route-wide rate}: \VthreeCorridorCamZeroCount{} $=$ \VthreeCorridorCamZero{} on CAM0,
against \VthreeCamZeroPrecision{} (\VthreeCamZeroWilson{}) over all its match
labels. \textbf{Its CAM5 half was withdrawn} for a defect found in the sealed
labels themselves: the viewer displaced Run B by the measured pose offset instead
of its negation, and the annotator's slider corrections correlate with the
mapping's errors (\texttt{TOOL\_DEFECT\_cam5.md}). CAM0's offset is zero, so
CAM0 stands. CAM5 was re-asked on \VthreebLabels{} fresh queries under its own
freeze, sign fixed, every row at the \VthreebPoseDefault{}\,px default:
corridor \VthreebCorridorCamFiveCount{} $=$ \VthreebCorridorCamFive{}
(\VthreebCorridorCamFiveWilson{}), \VthreebCamFivePrecision{}
(\VthreebCamFiveWilson{}) overall, \VthreebCamFiveWithinTwo{} within two
frames, and its errors are late-biased (median \VthreebSignedMedian{},
\VthreebSignedLater{}:\VthreebSignedEarlier{} late:early).

\textbf{Part of that bias is one pre-measured constant.} The matcher's ``same
place'' is image content; the labels' is a world position. The 18.5\,px gap
between the two --- \ConventionConstantFrames{} frames at CAM5's sweep rate ---
was measured on the v2 labels before this set was drawn. Shifting every CAM5
prediction by the rounded \ConventionShiftFrames{}, the submitted file
\emph{unchanged}, gives \ConventionShiftedCount{} $=$
\ConventionShiftedPrecision{} (\ConventionShiftedWilson{}) against
\ConventionUnshiftedPrecision{} at $0$ and \ConventionShiftedAtThree{} at $-3$:
overlapping intervals, a peak located rather than resolved. Two controls bound
it. On the v2 CAM5 labels the same shift is \textbf{neutral}
(\ConventionVtwoCamFiveAtZeroPrecision{} at $0$ and at $-2$), which is what a
mixture predicts: those labels used the marker direction for some queries and
the image layout for others ($dx$ s.d.\ 29.8\,px about a $-56$\,px median). On
CAM0, whose offset is zero, the sweep peaks at \ConventionVthreeCamZeroPeak{}
(\ConventionVthreeCamZeroAtZero{} falling to \ConventionVthreeCamZeroAtTwo{}).
So: a convention constant on a consistently labelled set, neutral on the mixed
one, and the two blind CAM5 readings (\VthreebVtwoPrecision{},
\VthreebCorridorCamFive{}) are not distinguishable at $n{=}32/15$. A sensitivity
reading on spent sets, not a held-out number; \S4 attaches the constant.

The kink claim replicates on CAM0 in direction only (\VthreeKinkMissCamZero{}
against \VthreeCorridorMissCamZero{}) and \emph{not} on CAM5
(\VthreebKinkMissCamFive{} against \VthreebCorridorMissCamFive{}). The slope
gate buys \VthreeSlopeGateCamZero{} on CAM0 for coverage
\VthreeSlopeGateCamZeroCoverage{} and \emph{costs} precision on CAM5
(\VthreebSlopeGateCamFive{}); the exposure gate costs CAM0 precision
(\VthreeDarkGateCamZero{}), all \VthreeDarkCamZeroCount{} CAM0 dark labels being
right. The unsubmitted slope variant beats the shipped mapping on both cameras
(\VthreeVariantCamZero{}/\VthreebVariantCamFive{}).

\subsection{Abstention: what the labels cannot say, and what can}

The v2 set held no true no-correspondence case, so it could not evaluate
abstention, and an earlier reading that abstention had collapsed is withdrawn.
Each targeted set supplies one such query: all six methods accepted v3's, and
\VthreebNoCorrespondenceRejectingMethods{} rejected the redo's.

Withholding a stretch of Run B supplies more: frames whose partner lay inside it
have none by construction. Detection at 60/150/400-frame holes runs
\AbstentionCamZeroByWidth{} on CAM0, rising with the hole as it should, but
\emph{falls} on CAM5 (\AbstentionCamFiveByWidth{}) at
\AbstentionFalseAlarmCamFive{} false alarms against \AbstentionFalseAlarm{};
\AbstentionTrials{} trials per cell, no interval: read the direction, not the digits. The route also supplies one
\emph{real} absence, found by looking at frames: an oncoming lorry fills the
Run B CAM0 image at \OcclusionInterval{}, so those descriptors describe a side
panel, not a place. Both mappings drive straight through it --- \OcclusionRows{}
accepted rows at confidence 1.00, at most \OcclusionNullMax{} no-correspondence
probability from the posterior. Three code-level causes, verified by
inspection: a monotonic path with pinned endpoints is always complete, so ``no
correspondence'' is not representable; the sequence gate tests aliasing, not
existence (its longest window passed 100\% of frames); and geometry is
propagated between sampled checks --- reserving the top tier for frames actually
checked collapses it from \StrictGeometryBefore{} to \StrictGeometryAfter{} on
CAM0, so \textbf{\StrictGeometryUnverified{} of top-tier acceptances were never
verified}.

\subsection{Reading the two cameras}

CAM0 is the stronger result: every determinable query answered,
\TolVtwoCamZeroTwo{} within two frames and \SubCamZeroPrecision{} strict, against
\SparseCamZeroCoverage{} coverage for v1 --- and of the fifteen queries only v2
answered, eleven are strictly right. CAM5 is weaker (v1 accepts
\SparseCamFiveAccepted{} of 37), but its failure is a \emph{localisation bias},
not place confusion: \TolVtwoCamFiveTwo{} within two frames and
\TolVtwoCamFiveFive{} within five, against \SubCamFivePrecision{} strict. Two
measurements say why. \textbf{(i) The camera moved between the runs.} At the
matcher's own pairs the CAM5 scene sits at $dx = \CamFiveMatcherDx$\,px,
$dy = \CamFiveMatcherDy$\,px, at the annotator's pairs at
$dx = \CamFiveLabelDx$\,px, constant along the route; CAM0 is $0/0$ on both.
A depth-profile test over $\sim$190 pairs is \textbf{consistent with rotation}
rather than travel (CAM5 \ParallaxCamFiveOffset{} frames from the depth-uniform
position, CAM0 control \ParallaxCamZeroOffset{}) but at SE\,1.5 cannot separate
$0$ from $-1.8$ frames. \textbf{(ii) CAM5 is aimed low}: roughly 70\% of every
frame is near-field asphalt, and a label-free gradient-NCC sweep of the far
field gives a median $z$ against background of \EvidenceZCamFive{} on CAM5
against \EvidenceZCamZero{} on CAM0 --- half the cross-run evidence everywhere.

\subsection{A label-free signal, dense over the whole route}

CAM0 and CAM5 face opposite sides, so their alignments come from disjoint scenes
and fail near-independently. Comparing them is dense over \ConsistencyFrames{}
frames: median disagreement \ConsistencyMedian{} frame, p95
\ConsistencyPninetyfive{}. Run \emph{before any label existed}, it flagged
A1068--1110, where five queries later proved undeterminable, inside a difficulty
region covering 28\% of the route (the A1050--1450 fence corridor, the
A1500--1750 tree tunnel). It measures consistency, not correctness. It also
judged the variants built once the labels were spent. Five input-side changes
(greyscale, sky mask, both, parallax re-selection, a speed channel) move
\textbf{nothing}: p95 stays at \VariantPninetyfiveRange{} frames. One change to
the \emph{pooling} does: an unsupervised VLAD over the same masked tokens (32
words learned from the route, nothing trained) takes p95 from
\ConsistencyPninetyfive{} to \VladPninetyfive{} frames over \VladFrames{} frames
mapped by both cameras (\BaselineFrames{} before), lifts CAM5 coverage
\BaselineCoverageCamFive{}$\to$\VladCoverageCamFive{}, reads \VladSpentCamZero{}
strict on the spent CAM0 labels against \SubCamZeroPrecision{}, and leaves the
kinks (\VladKinkCamZero{}/\VladKinkCamFive{}) where they were: the mean pooling
is a bottleneck, the input side is not, and the kinks belong to stage 3. No
held-out number; not submitted.

\subsection{Where the submitted mapping is least reliable}

\textbf{CAM5 throughout} (\VthreebVtwoCount{} strictly correct): usable for coarse
retrieval, not frame-exact supervision. \textbf{Under-exposed frames:} the
exposure flag fires on \DarkRunBCamZero{} Run B CAM0 frames (one stretch runs
\DarkLongestStretch{}) and \DarkRunBCamFive{} on CAM5; \DarkAcceptedCamZero{}
accepted CAM0 and \DarkAcceptedCamFive{} CAM5 rows have a flagged partner
(\DarkStrongCamFive{} strong plus \DarkSequenceCamFive{} sequence-supported on CAM5). Dark matches dark almost
regardless of place, so that error is \emph{systematic}:
\VthreebDarkCamFiveCount{} CAM5 blind dark labels are right against
\VthreeDarkCamZeroCount{} on CAM0. \textbf{Implausible one-step jumps
(``kinks''):} the first difference of the mapping is a local speed ratio, and
the coarse search may not sustain more than $2\times$, so an increment of
\KinkThreshold{} in 0.1\,s is unreachable --- yet the mapping asserts
\KinkCamZero{} on CAM0 and \KinkCamFive{} on CAM5, all \texttt{accepted\_strong},
against \KinkPosteriorCamZero{} per camera for the posterior (all four computed
thresholds ship; at $K\ge\KinkLowThreshold$ it is \KinkLowCamZero{}/%
\KinkLowCamFive{} against \KinkLowPosteriorCamZero{}/\KinkLowPosteriorCamFive{}).
The cause is stage 3: greedy refinement behind a non-decreasing floor \emph{with
no slope prior}, so a collapsed structure score sends its argmax to the window
edge and the floor keeps it there (coarse path step \KinkCoarseMaxStep{} against
\KinkRefinedMaxStep{}; \KinkPinnedFrames{} frames pinned at $+\KinkRefineRadius$,
\KinkPinnedFramesMinus{} at $-\KinkRefineRadius$). The \texttt{-{}-refinement
slope} variant (a Viterbi with a slope prior and a bounded step) has no kinks by
construction; its case is cross-camera p95
\BaselinePninetyfive{}$\to$\SlopePninetyfive{} at unchanged coverage, better
structure scores in A880--940 (\SlopeWindowScore{} against
\SubmittedWindowScore{}) and both blind sets, at the cost of CAM0 closure
\BaselineClosureCamZero$\to$\SlopeClosureCamZero{}. It stays unsubmitted: the
submission was frozen before either blind set was opened; \S4 gates the
neighbourhood instead. \textbf{Anywhere abstention matters:} an empty
row means none \emph{under this method}, never an automatic negative.

\section{Downstream policy for training or testing}

\subsection{Leakage-safe split, decided before anything else}

Assign the split before sampling, descriptor extraction or calibration; group by
route, traversal date, rig and \emph{all} paired cameras, and keep the
loop-equivalent departure and arrival in one group as distinct occurrences.
Never randomise adjacent frames or treat CAM0 and CAM5 as independent. The
present design prevents label tuning but remains transductive: one route, one
pair of dates.

\subsection{The per-frame manifest: a schema, and what ships against it}

\texttt{frame\_manifest\_schema.json} is a closed schema, not a shipped table;
what ships against it is \texttt{frame\_quality\_flags.csv} plus the mapping
CSVs' own columns. Its fields: \textbf{identity} (policy version, run, camera,
source SHA-256, decoder, colour matrix and range, coded and display raster,
display-order ordinal); \textbf{time} (run start/end, and per-image capture time
\emph{explicitly null} with its reason: both cameras of a run share one
byte-identical sidecar that cannot describe both --- Run B decodes 2{,}622 and
2{,}615 frames against one 2{,}663-row log); \textbf{quality} (route phase, mask
version, \texttt{too\_dark} with its two luma measurements, \texttt{occluded},
\texttt{slope\_gate}, temporal cluster, sample weight); \textbf{governance}
(route/traversal group, split, boundary buffer, paired camera);
\textbf{correspondence} (partner or null, acceptable interval, typed status,
label source, freeze hash, known failures, and the camera-to-world convention
offset: CAM0 \ConventionCamZeroShift{}, CAM5 \ConventionShiftFrames{} frames for
world-position use --- measured on v2, validated on v3b, neutral on v2 itself).
It forbids four silent assumptions: sidecar row $i$ as decoded image $i$,
cameras synchronised by ordinal, coverage as accuracy, confidence as
probability. Two facts a consumer must know: \texttt{confidence} is an ordinal
rank whose \texttt{0.50} tier never occurs, and the mapping is
\textbf{many-to-one} (\ManyToOneCamZero{} of CAM0's mapped rows share a partner,
max \ManyToOneMaxCamZero{}; \ManyToOneCamFive{}, max \ManyToOneMaxCamFive{}, on
CAM5) --- expected where Run B is slower, fatal to a consumer keying on
\texttt{runB\_frame}.

\subsection{A posterior formulation, built but not claimed}

The three structural gaps in \S3.3 share one cause: the method had no posterior.
A hidden Markov model over Run B position with an explicit \emph{null} state
tests that reading (emissions are likelihood ratios against each query's own
similarity row; the \S3.3 holdout runs against it at a threshold set on synthetic
sequences, never on labels). Loop closure (one place in Run A must map to one in
Run B) reaches \PosteriorClosureCamZero{} consistent revisit pairs on CAM0 and
\PosteriorClosureCamFive{} on CAM5 against \BaselineClosureCamZero{} and
\BaselineClosureCamFive{} for the submitted method, unchanged by coupling; the
denominators differ because the submitted mapping abstains on some revisit ends.
Its suspension-shake channel needed correcting first: both cameras ride one
chassis, so a jolt must fire in both streams at once, and that label-free test
\emph{selects among three constructions}: raw frames \MotionCofireOldRunB{} on
Run B, temporal-mean division \MotionCofireRunB{} ($\MotionCofireRunBRatio\times$
chance, \MotionCofireRunA{} on Run A), median subtraction
\MotionCofireMedianRunB{}. The \MotionEventsOld{} event asymmetry was therefore
an artefact (\MotionEventsNew{} corrected), the ratio \MotionWithdrawnRatio{} is
withdrawn, and \MotionMappingIdenticalCamZero/\MotionMappingIdenticalCamFive\% of
the mapping is unchanged either way.

Both freezes named it, so it has a held-out score: \VthreePosteriorCamZero{} on
CAM0 and \VthreebPosteriorCamFive{} on CAM5 against \VthreeCamZeroPrecision{}
and \VthreebCamFivePrecision{} submitted; calibration error \EceCamZero{} and
\EceCamFive{} (the second overconfident); p95 disagreement 11 frames to 4. Not
submitted: the submission was frozen first, and its null state accepted both
sets' \texttt{no\_correspondence} query, alone among six on the redo's.
